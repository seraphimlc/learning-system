# AI 原生私人学习系统项目蓝图

版本：2026-07-04  
阶段：项目启动文档  
对象：即将升入初一的孩子  
当前优先级：数学优先，英语后续接入  

---

## 1. 项目一句话定义

我们要做的不是普通学习软件、刷题软件、网课替代品，也不是通用教育产品。

我们要做的是一套面向一个真实孩子的 AI 原生学习系统：

> 以知识图谱为底座，以诊断测试为入口，以模型化教学为核心，以少量高质量题为验证，以错因回退和动态规划为闭环，持续帮助孩子补齐小学关键漏洞，并高效预学初中知识。

它的本质不是“软件功能集合”，而是一个可以在真实教学过程中自迭代、自演进的 AI 教研系统。

## 3. 项目目标

### 3.1 暑假第一阶段目标

在 2026-08-24 开学前，让孩子达到：

- 小学数学中影响七上的关键漏洞得到补齐。
- 能跟住人教版七年级上册数学主线。
- 对有理数、代数式、整式加减、一元一次方程、几何图形初步有基本理解。
- 能做基础题和部分中档题。
- 遇到题目能先判断考点和模型，而不是看到数字就乱算。
- 出错后能定位是概念、计算、审题、模型、步骤习惯还是遗忘。
- 建立基本学习信心，不再只靠题海硬刷。

暑假结束后，不假设系统已经完美。

下一阶段根据孩子真实学习数据继续演进：

- 初一上学期跟踪
- 校内考试与作业反馈
- 知识图谱修正
- 个性化复习路径
- 更细的错因模型
- 更适合孩子的讲解方式和题型梯度

## 4. 关键共识

### 4.1 不做什么

- 不做通用教育产品。
- 不做多用户系统。
- 不做一开始就巨大完整的平台。
- 不做题海战术。
- 不做机械日历式计划。
- 不按小学三到六年级逐章全量复习。
- 不把奥数、竞赛题作为主线。
- 不凭感觉说孩子哪里弱。
- 不用“粗心”掩盖真实错因。

### 4.2 要做什么

- 做给这个孩子一个人用的系统。
- 做一个阶段一个阶段演进的系统。
- 先做数学，再做英语。
- 先做知识图谱，再做诊断，再做计划和页面。
- 用少量高质量题定位问题、验证掌握。
- 用模型化教学讲透知识点。
- 用错因回退机制决定下一步。
- 用真实学习数据驱动系统迭代。

## 5. AI 原生系统范式

传统软件工程通常适合：

- 需求明确
- 流程固定
- 状态可枚举
- 输出可预测
- 模块边界稳定
- 业务逻辑长期不变

这个项目不完全适合传统软件范式，因为：

- 孩子的认知状态会变。
- 学习路径会变。
- 知识图谱会变。
- 题目、讲法、难度梯度会变。
- Agent 能力会变。
- 家长反馈会改变系统判断。
- “做对”不等于“真懂”，“做错”也要判断错因。

因此本系统采用：

> 稳定的数据骨架 + 可进化的 AI 教研层 + 简洁的孩子学习端。

传统软件负责“骨头”，AI 负责“生长”。

## 6. 整体系统形态

系统分为两端：

### 6.1 儿子端

儿子端是孩子实际使用的学习页面。

特点：

- 简单
- 少干扰
- 任务明确
- 页面上能讲知识
- 页面上能做题
- 能标记正确、错误、部分正确
- 能显示必要反馈
- 不暴露复杂教研逻辑

儿子端不是后台，不应该复杂。

### 6.2 家长端 / Codex 端

家长端主要在 Codex 中进行。

它是 AI 教研后台，不是普通管理后台。

功能：

- 和 AI 一起复盘孩子表现
- 管理知识图谱
- 生成诊断测试
- 设计讲解
- 生成题目
- 分析错因
- 调整计划
- 演进 agent 能力
- 决定下一次儿子端页面内容

### 6.3 数据流

```text
知识图谱
  ↓
诊断测试
  ↓
孩子当前状态模型
  ↓
AI 生成今日学习任务
  ↓
儿子端讲解与做题
  ↓
答案、过程、错因、耗时、家长观察
  ↓
Codex 家长端复盘
  ↓
Agent 群分析与规划
  ↓
更新孩子画像、计划、题目、必要时更新知识图谱
  ↓
生成下一次儿子端学习任务
```

## 7. Agent 群设计

Agent 不是为了炫技，而是为了让 AI 教研工作分工明确、互相校验。

### 7.1 图谱 Agent

职责：

- 维护数学/英语知识图谱
- 管理节点拆分、合并、依赖关系
- 判断哪些小学前置影响初一
- 判断哪些节点是核心、选择性核心、受控拓展
- 根据真实学习数据修正图谱

关键原则：

- 图谱不是静态大纲。
- 如果孩子持续在某类题上卡住，要考虑节点是否太粗、缺前置或依赖错误。

### 7.2 诊断 Agent

职责：

- 基于图谱设计诊断题
- 每道题绑定知识节点
- 每道题绑定可能错因
- 根据结果给节点打 A/B/C/D 状态
- 决定是推进、复测、补救还是回退

诊断不是考试，不是打击孩子，而是定位断点。

### 7.3 教学 Agent

职责：

- 把知识点讲成孩子能懂的形式
- 生成“一句话本质”
- 设计核心模型
- 设计标准例题
- 设计变式讲解
- 根据孩子反应更换讲法

可用讲法包括：

- 线段图
- 表格
- 数轴
- 生活情境
- 天平模型
- 圆周/环形追及模型
- 实物或图形直观
- 从算术到代数的过渡

### 7.4 出题 Agent

职责：

- 围绕节点生成标准题、变式题、迁移题、复测题
- 控制难度梯度
- 避免题海
- 针对高频错因生成修复题
- 让题目服务诊断和教学，而不是堆数量

每个节点题目梯度：

- L1 识别：判断考点/规则
- L2 套用：直接计算或列式
- L3 变式：换语境、换数字、加干扰条件
- L4 迁移：和前后知识点混合

### 7.5 错因 Agent

职责：

- 分析错题原因
- 区分概念、计算、审题、模型、步骤习惯、遗忘
- 把“粗心”拆成具体原因
- 决定回退到哪个前置节点

主要错因标签：

- `calculation_or_symbol`：计算、符号、括号、通分约分、小数点等错误
- `concept_confusion`：概念意义、分类、单位1、表示方法不清
- `modeling_or_reading`：读题、等量关系、模型选择、单位统一问题
- `process_habit`：跳步、漏检验、书写不规范、草稿不可复查
- `visual_spatial`：几何图形、空间想象、标图关系错误
- `memory_or_fluency`：记忆不熟、提取慢、基本事实不流畅

### 7.6 计划 Agent

职责：

- 根据节点状态动态安排每日学习
- 不做固定死计划
- 不按“一个知识点一周”粗暴排课
- 结合可用时间、诊断结果、复测周期、主线进度进行调度

计划原则：

- 每天约 1 小时。
- 数学当前优先级更高。
- 小学计算只做维护和补漏洞，不单独拖成一周专题。
- 已掌握节点只安排间隔复测。
- 薄弱节点要微课 + 少量变式 + 隔天复测。
- 卡死节点要回退前置链。

### 7.7 评估 Agent

职责：

- 阶段性判断目标完成度
- 判断是否可以进入下一模块
- 判断是否需要收缩目标
- 判断是否可以适度加拓展
- 给家长生成阶段报告

### 7.8 家长助手 Agent

职责：

- 把复杂教研结论翻译成家长可执行动作
- 告诉家长今晚考哪几题
- 告诉家长观察什么
- 帮家长记录孩子表现
- 生成下一次会话所需上下文

## 8. 核心教学方法

每个知识点都按以下结构设计：

1. 一句话本质
2. 前置知识
3. 核心模型
4. 标准例题
5. 变式题
6. 易错点
7. 少量检测
8. 错因回退
9. 间隔复测

### 8.1 一句话本质

孩子先知道这个东西到底在干什么。

例：

- 追及问题：距离差随着速度差在变化。
- 方程：用等号把未知数和已知条件连接起来。
- 绝对值：一个数到 0 的距离。
- 去括号：括号前是负号，每一项都要变号。

### 8.2 核心模型

重点不是背公式，而是理解模型。

例如：

- 行程基础：路程 = 速度 × 时间
- 相遇：距离和按速度和变化
- 追及：距离差按速度差变化
- 钟表角：角度版环形追及
- 分数应用题：单位1、分率、具体量
- 方程应用题：设未知数、找等量关系、解方程、检验

### 8.3 少量高质量题

每天题量不宜多。

推荐结构：

- 1 道标准题
- 2 道变式题
- 1 道错因复测题
- 必要时加 1 道迁移题

题目要能暴露问题，而不是让孩子机械刷熟。

### 8.4 错因回退

错了不直接刷同类题。

先问：

- 是概念不懂吗？
- 是计算错吗？
- 是符号错吗？
- 是读题错吗？
- 是模型选错吗？
- 是等量关系写反吗？
- 是步骤跳了导致不可复查吗？
- 是旧知识前置断了？

然后沿知识图谱回退。

## 9. 数学重点策略

数学不是平均用力。

重点由以下因素决定：

```text
高频 + 高迁移 + 高易错 + 高前置价值 = 重点优先
```

### 9.1 底层计算重点

包括：

- 整数四则
- 小数运算
- 分数运算
- 四则混合
- 括号
- 符号
- 简便计算
- 估算

目的不是刷速度，而是保证初一有理数、代数式求值、方程不被计算拖死。

### 9.2 数感与估算重点

包括：

- 结果范围
- 小数点位置
- 分数大小
- 正负号合理性
- 估算检验

这能减少大量“会做但错”的问题。

### 9.3 应用题模型重点

包括：

- 和差倍
- 归一归总
- 工程
- 行程
- 追及
- 相遇
- 环形
- 钟表角
- 比例
- 百分数

这些不是孤立题型，而是训练从文字提取关系的能力。

### 9.4 初一衔接重点

包括：

- 正负数
- 数轴
- 相反数
- 绝对值
- 有理数运算
- 代数式
- 整式加减
- 一元一次方程
- 几何图形初步

这是暑假数学主线。

### 9.5 受控拓展

包括：

- 钟表角
- 环形追及
- 复杂比例
- 变式行程题
- 部分奥数思想

这些题服务模型迁移，不服务炫技。基础不稳时不展开。

## 10. 钟表角示例的教学意义

用户曾举例：

> 7 点多少分的时候，分针落后时针 100 度？

这个题不是孤立题，它暴露了本系统的教学思路。

### 10.1 表面知识

- 钟面一圈 360°
- 每大格 30°
- 分针每分钟 6°
- 时针每分钟 0.5°

### 10.2 深层模型

这是角度版的环形追及问题。

核心是：

```text
相对速度 = 6°/分 - 0.5°/分 = 5.5°/分
```

### 10.3 考察点

- 圆周角度
- 初始位置
- 领先/落后方向
- 相对运动
- 方程思想
- 是否理解夹角与方向角

### 10.4 教学路径

不是直接教公式，而是：

1. 把钟面看成 360° 圆周。
2. 把分针和时针看成两个运动点。
3. 先算 7 点整初始角度。
4. 判断谁追谁、差多少。
5. 用相对速度列式。
6. 讨论是否有另一个角度答案。

这就是“围点打圆、举一反三”：从一道题链接行程、追及、角度、方程。

## 12. 诊断状态模型

每个节点的学习状态分为：

### A 已掌握

- 正确率 ≥ 85%
- 能讲清方法
- 能做一道小变式
- 后续只做间隔复测

### B 不稳定

- 正确率 60%-85%
- 或需要提醒才能做
- 安排微课 + 少量变式 + 隔天复测

### C 薄弱

- 正确率 < 60%
- 或概念说不清
- 回退前置节点补

### D 卡死

- 当前节点错
- 前置链条也错
- 暂停当前七上内容
- 补最早断点

## 13. 每日学习基本模板

每天约 1 小时。

建议模板：

```text
5 分钟：旧错题复测
15 分钟：讲一个知识点本质/模型
25 分钟：3-5 道高质量变式题
10 分钟：错因归类与回退判断
5 分钟：记录明天复测点
```

注意：

- 这只是模板，不是死规定。
- 如果当天诊断发现卡死，要立刻回退。
- 如果孩子状态差，降低题量，保证质量。
- 如果孩子已经掌握，快速通过，不拖时间。

## 14. 英语已有讨论与资产

## 15. 儿子端第一版设想

第一版不追求复杂。

### 15.1 页面能力

至少包括：

- 今日任务
- 知识点讲解
- 标准例题
- 做题区
- 对/错/部分正确标记
- 错因选择
- 简单反馈
- 下一步建议

### 15.2 数据记录

每次学习记录：

- 日期
- 学科
- 节点 ID
- 题目 ID
- 答案
- 正确/错误/部分正确
- 错因标签
- 用时
- 孩子是否能解释
- 家长备注
- 下一步动作

### 15.3 儿子端设计原则

- 页面不能吓人。
- 不显示复杂图谱。
- 不显示过多任务。
- 每次只聚焦一个主知识点。
- 反馈要具体，不要只说“错了”。
- 不要让孩子感觉像被系统审判。

## 16. 家长端 / Codex 端第一版设想

家长端先不一定做传统 Web 后台。

Codex 就是第一版家长端和教研后台。

### 16.1 家长在 Codex 中做什么

- 查看今天任务
- 打印或打开儿子端页面
- 记录孩子做题情况
- 告诉 AI 哪些题对、哪些题错、错在哪里
- 让 AI 分析错因
- 让 AI 更新计划
- 让 AI 生成下一次学习页面

### 16.2 家长不是老师

家长不需要懂教学体系。

家长主要做：

- 观察孩子真实反应
- 记录孩子是否会讲思路
- 标记对错
- 输入备注
- 把实际情况反馈给 AI

教学架构、图谱、诊断、计划、出题由 AI 承担。

## 17. 自迭代与自进化机制

系统必须可以自己根据实际教学情况做动态规划和动态演进。

### 17.1 知识图谱迭代

触发条件：

- 某类题连续错
- 明明讲了但不会迁移
- 错因无法归入现有节点
- 当前节点太粗
- 缺少关键前置

动作：

- 拆分节点
- 新增前置节点
- 调整依赖
- 调整优先级
- 调整是否为暑假核心

### 17.2 孩子画像迭代

持续记录：

- 哪些节点 A/B/C/D
- 高频错因
- 哪些讲法有效
- 哪些题型容易卡
- 是否有畏难或注意力问题
- 哪些知识容易遗忘

### 17.3 题型库迭代

根据表现：

- 错得多的地方生成更多变式
- 掌握好的地方减少重复
- 增加迁移题
- 删除无效题
- 调整难度阶梯

### 17.4 教学策略迭代

如果一种讲法无效，换：

- 线段图
- 表格
- 数轴
- 实物模型
- 天平模型
- 运动模型
- 生活类比
- 反例辨析

### 17.5 计划迭代

计划不是日历，而是动态调度器。

每天根据：

- 昨天结果
- 复测结果
- 错因类型
- 当前时间窗口
- 主线进度
- 孩子状态

重新安排下一步。

## 18. 数据结构原则

第一版必须留好演进接口。

核心对象包括：

### 18.1 KnowledgeNode

知识节点。

必须有：

- 节点 ID
- 名称
- 学段/阶段
- 优先级
- 前置节点
- 解锁节点
- 本质解释
- 易错点
- 诊断探针
- 掌握标准
- 教学策略
- 补救路径
- 出题梯度

### 18.2 Question

题目。

必须有：

- 题目 ID
- 绑定节点
- 难度层级
- 题型
- 标准答案
- 解题步骤
- 可能错因
- 是否诊断题
- 是否复测题

### 18.3 Attempt

作答记录。

必须有：

- 日期
- 题目 ID
- 节点 ID
- 答案
- 结果
- 用时
- 错因
- 家长备注
- 孩子解释评分

### 18.4 LearnerNodeState

孩子在某节点上的状态。

必须有：

- 节点 ID
- 状态 A/B/C/D
- 最近得分
- 能否解释
- 最近复测日期
- 下次复测日期
- 推荐动作

### 18.5 PlanItem

每日计划项。

必须有：

- 日期
- 学科
- 节点 ID
- 任务类型
- 预计时间
- 题目列表
- 复测点
- 完成结果

## 21. 重要教育边界

### 21.1 关于教材和资料

不能假装拥有私有教材、教辅或题库。

如果后续要严格对齐人教版教材、孟建平等教辅、奥数资料，需要：

- 用户提供实物教材目录或照片
- 用户提供教辅题目
- 或使用可合法访问的公开资料，并记录来源

### 21.2 关于题库

系统可以生成题，但不能盲目堆题。

高质量题应该服务：

- 诊断
- 教学
- 迁移
- 复测
- 错因修复

### 21.3 关于拔高

可以吸收奥数、竞赛、俄罗斯数学等不同教学体系中的模型意识和思维训练，但必须有度。

当前孩子数学 80 分，主线是：

1. 补基础漏洞
2. 建立初一代数主线
3. 形成稳定解题习惯
4. 再做适度迁移与拓展
