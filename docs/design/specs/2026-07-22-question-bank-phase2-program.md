# 第二阶段：高质量题库持续生产方案

状态：`PHASE_2_STARTED`

日期：2026-07-22

## 结论

系统现在必须从“功能连续性优先”切换到“教研资产质量优先”。

第一阶段目标是让学习链路跑起来：选题、答题、保存、批阅、反馈、下一步。这个阶段已经证明了工程链路可以运转，但题库质量暴露出明显问题。

第二阶段目标是建立可持续出题系统：题不是一次性凑 1000 道，而是持续生产、持续审查、持续入库、持续淘汰。命题 Agent 必须变成一个有知识体系、题型体系、难度体系和审查体系的教研生产者。

## 外部参照原则

可以参考外部公开资料，但不能复制私有教材、教辅或商业题库。

本阶段允许使用：

- 义务教育数学课程标准，用来校准能力目标和学业质量。
- 人教版七上公开目录，用来校准知识范围。
- 可汗学院等公开课程结构，用来参考知识组织方式。
- 公开样题/单元测试的题型结构，用来观察题型分布。

不允许：

- 直接搬运整套商业题库。
- 把版权题改数字后入库。
- 声称拥有某本教辅的完整题库。
- 用外部题库替代自家图谱节点和孩子画像。

## 专家组

第二阶段不再只靠一个命题 Agent。至少需要 6 类专家视角。

### 1. 课程标准专家

职责：

- 判断题目是否符合七年级上册学习范围。
- 判断是否超纲或过低龄。
- 判断题目能力目标是否和课程标准方向一致。

不做：

- 不负责生成具体题。
- 不负责 UI。

### 2. 一线数学教师

职责：

- 判断孩子是否能看懂题面。
- 判断题目是否像真实课堂会问的问题。
- 判断标准答案是否自然。
- 判断错因是否真实。

不做：

- 不追求题目花哨。
- 不只看答案是否唯一。

### 3. 竞赛/拔高教练

职责：

- 设计受控拔高题。
- 判断 L4/L5 是否真的有迁移价值。
- 避免把奥数题塞进主线。

不做：

- 不让拔高题抢基础诊断。
- 不用难题证明系统厉害。

### 4. 认知诊断专家

职责：

- 判断一道题能暴露什么认知断点。
- 判断错因能否映射到图谱节点。
- 判断题目是否能区分“会算但不理解”“答案碰巧对”“表达不完整但理解正确”。

不做：

- 不把所有问题归为粗心。

### 5. 评分合同专家

职责：

- 设计关键得分点。
- 区分主分、部分分、非关键书写。
- 保证孩子表达意图正确时不被误判低分。

不做：

- 不把标准答案写法当唯一答案。

### 6. 观止 QA

职责：

- 做题库质量门。
- 查节点错配、题型换皮、答案错位、低龄题、过难题、浏览器渲染问题。
- 做抽样真实流程验证。

不做：

- 不只看测试是否退出码为 0。

## 生产流水线

### Step 1：节点蓝图

每个图谱节点必须先有蓝图。

蓝图包含：

- 节点能力一句话。
- `scope_in`
- `scope_out`
- 真实题型家族。
- 难度预算。
- 典型错因。
- 回退节点。
- 必须拒绝的错配题型。

没有蓝图，不允许生成题。

### Step 2：题型家族库

题型家族不是“选择/填空/解答”这种表面形式，而是数学任务结构。

例子：

- 有理数加减：同号相加、异号相加、减法转加法、多项加减、错解修复、数轴解释。
- 工程问题：总量为 1、单独效率、合作效率、先后合作、错误模型辨析。
- 展开图与视图：展开图可行性、相对面判断、三视图匹配、小正方体数量推断。

### Step 3：小样本生成

每个簇先选 2 个节点，每节点 6 道。

总量约 60 道。

这一步只验证生成策略，不追求数量。

### Step 4：多专家审查

每道样题至少过三道门：

- 课程/范围门。
- 教研/题面门。
- 认知/评分门。

任何 P0 问题，整组重做。

### Step 5：全量生成

小样本通过后，才允许生成全量候选池。

全量候选池目标：

- 800-1000 道。
- P0 节点 16-22 道。
- P1 节点 10-16 道。
- P2 节点 6-10 道。

### Step 6：入库前验收

必须通过：

- 去重。
- 节点匹配。
- 题型家族分布。
- 难度分布。
- 评分合同生成。
- 观止抽样浏览器流程。

没过就不激活。

## 持续生产机制

后续题目会源源不断生成，因此题库不能只有“全量 rebuild”。

需要三类生产模式：

### 1. 批量生产

用于补齐节点候选池。

输入：

- 节点蓝图
- 题型家族
- 难度预算

输出：

- 候选题
- 审查结果
- 可入库题

### 2. 课后定向生产

用于孩子某次学习暴露薄弱点后，生成 1-3 道精准复测题。

输入：

- 最近 attempts
- answer_analysis
- mastery_update
- weak dimension
- 当前节点蓝图

输出：

- same-structure confirmation
- near-transfer retest
- prerequisite probe

### 3. 拔高生产

用于孩子已经稳定掌握后，生成受控拔高题。

输入：

- 已掌握节点
- 可组合节点
- L4/L5 family

输出：

- 迁移题
- 边界题
- 小竞赛味题

拔高题不允许反向否定基础掌握。

## 关键工程要求

### 题目状态

题目不能一生成就 active。

状态应为：

- `draft_generated`
- `self_checked`
- `expert_reviewed`
- `qa_passed`
- `active`
- `retired`
- `rejected`

### 版本管理

每道题必须记录：

- generator version
- blueprint version
- family version
- reviewer version
- scoring contract version

### 淘汰机制

题目被孩子使用后，如果出现这些情况，应进入 review：

- 孩子普遍看不懂题面。
- 标准答案导致误判。
- 多次暴露同一题面歧义。
- 规划 Agent 使用该题后得出错误下一步。

## 第二阶段近期目标

### P0

- 完成 `node_question_blueprints_v18.json`。
- 完成 `question_type_taxonomy_v18.json`。
- 完成 60 道小样本。
- 完成多专家审查报告。

### P1

- 改造命题 Agent prompt，使其只能按蓝图出题。
- 改造审题 Agent prompt，使其按节点蓝图拦截。
- 增加题库 QA 自动检查脚本。

### P2

- 引入公开参考题型索引，不复制题，只记录题型结构。
- 建立题目使用后的质量反馈机制。

## 阶段门

第二阶段不能跳过小样本直接生成 1000 题。

允许进入全量生成的条件：

- 60 道小样本专家审查通过。
- 每个簇至少一个节点浏览器真实流程通过。
- 观止没有发现节点错配 P0。
- 评分合同专家确认评分不误伤孩子等价表达。
