# Admin Console PRD v1

Status: `PRD_REVISED_FOR_REQUIREMENT_SLOT_WORKFLOW`

Owner: 若命

Created: 2026-07-23

Scope: 独立 Codex 管理模块，用于科目、知识资产、题源、题库库存、答案合同、审核和运行配置管理。它不是儿子端，也不是家长端，也不提供 Web UI。

## 结论

系统需要第三个独立模块：`Admin Console`。

它的第一形态不是 Web UI，而是 Codex 可查询、可执行、可审计的管理能力。也就是说，管理端通过 Codex 命令、文档、SQLite/JSON 管理工具和报告工作流完成管理，不为家长或孩子增加一个后台网页。

三端边界如下：

| 端 | 使用者 | 做什么 | 不做什么 |
|---|---|---|---|
| 儿子端 | 孩子 | 学习、答题、看讲解、看自己的知识进度 | 不看题库状态、模型配置、内部图谱 ID、审核流程 |
| 家长端 | 家长 / Codex | 查学习证据、日报、问题、进展和系统风险 | 不做平台配置，不人工批阅题目 |
| 管理端 | 平台管理者 / 若命团队，通过 Codex 使用 | 管理科目、图谱、题源、题库库存、答案合同、专家审核、模型配置和内容质量 | 不做 Web UI，不替孩子学习，不管理孩子个人进度，不替家长做学习解释 |

管理端的核心价值不是“多一个后台页面”，而是把题库、图谱、知识卡、专家审核、模型配置和激活门禁从代码脚本里拿出来，变成可追溯、可审核、可回滚的系统资产生产线。

## 当前决策

- 管理端是独立功能模块，后续可以有独立路由、权限和数据边界。
- 管理端第一版只做 Codex 查询和管理动作，不做 Web UI。
- 管理端只管理科目、知识资产和库存相关事项，不管理孩子个人学习流程或学习进度。
- 管理端可以读取孩子学习状态的聚合分析，用于调整题库内容、补题、退题、改评分合同和优化节点覆盖；这些分析不能成为孩子端掌握状态的写入入口。
- 教育专家可以不止一个，且不同专家承担不同审核责任。
- 题库初始化允许使用已有题，但必须按来源、授权和用途分级管理。
- 不要求所有题都由 AI 生成；正确模式是“授权题源 / 开放题源 / 题型参考 / AI 原创生成 / 专家审核”混合生产。
- 管理端必须支持 v18.1 题库生产线，而不是绕过它直接把题放进孩子端。
- 题库生产的边界已修正：专家定义逐题 requirement，命题 Agent 只按单个 requirement 出题，程序 workflow 负责检查、退回、重出和升级，不允许生产线自己发明题型 slot。

## 设计来源

Confirmed:

- 用户确认当前已有儿子端和家长端，需要新增独立管理端。
- 用户确认管理端只做 Codex 查询，不做 Web UI。
- 用户确认管理端只管科目、库存相关事项，不直接管理孩子和学习进度。
- 用户确认管理端可分析孩子学习状态来调整题库内容。
- 用户确认当前没有可提供的商业/教辅材料，系统自行寻找候选题源；没有授权时只做公开信息和结构分析。
- 用户确认管理沟通和审核可以先用 Markdown 等轻量文档方式完成，不需要 Web UI。
- 用户确认学习状态输入到题库调整的粒度可以到节点、题型家族和单题误判事件。
- 用户确认教育专家可以不止一个。
- 用户确认题库初始化可以找已有题来用，不要求全部生成。
- 项目边界仍是单个孩子定制学习系统，数学优先，不做题海。

Observed:

- 题库 v18.1 已定义生产线：图谱节点 -> 节点蓝图 -> 题型家族 -> 单题生成 -> 答案与评分合同 -> 机器校验 -> AI 审题 -> 多专家评审 -> 小样本真实验证 -> staged -> active。
- 当前题库、知识图谱、学习记录、答案合同已经开始分离，但管理能力仍主要散落在脚本和文档中。

Referenced external source examples:

- OpenStax Prealgebra 2e 公开页面标注 CC BY-NC-SA 4.0，可作为前代数范围和题型结构候选参考，但直接使用、改编、署名、派生作品共享方式和 AI 摄入边界仍需按具体页面确认。
- Illustrative Mathematics / Open Up Resources / CK-12 等开放教育资源可作为候选题源清单，但当前环境未完成逐项许可核验，不能在管理端默认标记为可直接导入。
- 不因为“开放教育资源”四个字就默认可直接入库或用于模型生成。
- 商业题库、教材和教辅可以做公开目录、样章、题型分布、难度梯度和知识覆盖分析；除非用户提供合法授权或明确可使用许可，不抓取、不复制、不批量保存其题干、答案、解析、图片或版式内容。

题源发现责任：

- 管理端负责主动维护候选题源清单，包括开放教育资源、公开教材目录、出版社公开样章、教师公开讲义、竞赛公开样题说明和用户后续提供的授权材料。
- 每个候选题源先生成 Markdown `source_analysis_receipt`，记录来源、链接、许可观察、可用范围、禁止范围、适合映射的图谱节点和推荐使用方式。
- 未完成 receipt 和许可核验前，候选题源不能进入 `direct_import` 或 `adapted_import`。

## 用户与角色

### 平台管理者

管理系统资产和运行规则。当前通过 Codex 操作，未来仍优先保持 Codex 管理，不默认增加 Web 后台。

### 教育专家

可以有多个专家角色：

| 专家类型 | 负责什么 | 不负责什么 |
|---|---|---|
| 一线初中数学老师 | 判断是否符合六升七真实水平、是否能教会孩子 | 不负责系统架构 |
| 衔接诊断老师 | 判断前置漏洞、回退链和诊断效率 | 不追求题量 |
| 拔高 / 竞赛老师 | 判断 L4/L5 题是否有思维价值 | 不把奥数当主线 |
| 测评专家 | 判断题目能否产生掌握证据，评分合同是否合理 | 不只看答案对错 |
| 题源合规 reviewer | 判断来源、许可、署名、改编边界是否清楚 | 不提供法律结论 |

专家不仅是质量门禁，也要参与题型设计。每个专家都应能提出自己负责视角下的题型构思：

- 一线老师提出孩子愿意做、能理解、能体现课堂价值的题面方式；
- 衔接诊断老师提出能暴露前置断点和回退路径的探针题型；
- 拔高老师提出边界、反例、逆向、迁移和小竞赛味的受控拓展；
- 测评专家提出证据目标、评分点、等价表达和误判防线；
- 题源合规 reviewer 提出可参考的结构边界和必须原创的内容边界。

这些构思是命题 Agent 的 generation brief，不是 active 题目，也不直接进入孩子端。

### 内部 Agent

管理端不把 Agent 暴露给孩子。管理端允许管理员查看和配置：

- 命题 Agent 的题型家族、生成策略、禁区和输出合同；
- 审题 Agent 的拒绝规则；
- 答案分析 Agent 的评分依据；
- 评估 / 规划 Agent 的输入边界；
- 观止、镜花、清秋、教育专家的审核结果。

## 管理端模块

### 0. Codex 管理入口

管理端第一版不是页面，而是一组 Codex 可执行能力：

- 查询科目、图谱、知识卡、题库库存、题源和审核状态；
- 生成题库库存报告；
- 发起小批题库生产；
- 发起题源许可核验；
- 发起教育专家审核；
- 发起专家题型构思；
- 查看激活门失败原因；
- 查询孩子学习聚合信号对题库的影响建议；
- 生成题库补齐、下架、返修和评分合同修订任务。

Codex 输出必须可追溯：

- 查询条件；
- 数据来源；
- 使用的数据库/JSON/Markdown 文件；
- 是否读取了孩子学习聚合信号；
- 是否产生写入动作；
- 后续需要谁审核。

限制：

- 不在 Codex 输出里泄漏给孩子端的隐藏内容；
- 不把一次查询结果当成 active 激活凭证；
- 不通过管理端直接写孩子 mastery；
- 不把商业题库抓取结果直接写入题库。

### 1. 科目管理

管理数学、英语等科目及阶段目标。

MVP 范围：

- 科目名称；
- 当前阶段，例如“小升初衔接”“七上预学”；
- 启用状态；
- 默认知识图谱版本；
- 默认题库版本；
- 默认学习卡集合。

Non-goal:

- 不做多学校、多班级、多学生管理。

### 2. 知识图谱管理

管理知识点节点和依赖关系。

必须支持：

- 节点查看、搜索、筛选；
- 节点阶段、模块、难度、掌握标准；
- 严格前置依赖；
- 解锁候选关系；
- 回退候选节点；
- 节点是否允许进入儿子端；
- 图谱版本和变更记录。

关键约束：

- 图谱是教学结构事实源。
- 导图、目录、学习入口只是投影，不改变底层图谱事实。

### 3. 知识卡管理

管理每个知识点的学习内容。

必须支持 child-facing 和 internal 两层：

- child-facing：孩子能看的解释、互动、图形、动画、例题、提示；
- internal：知识本质、误解模型、前置依赖、掌握证据、适合组件、禁用表达。

知识卡不是统一模板。每个知识点应根据数学本质选择表达方式：

- 数轴类可用拖点、移动、比较；
- 方程类可用天平、等量变换、步骤回放；
- 应用题可用关系图、线段图、表格；
- 几何类可用标注图、折叠/旋转/视图切换；
- 计算类应少做机械题，多做结构、估算、检验和迁移。

### 4. 题源管理

管理已有题、开放资源、用户提供材料、商业教材教辅分析记录和 AI 原创题的来源。

题源字段：

- `source_id`
- `source_name`
- `source_type`: `user_owned`, `open_license`, `commercial_reference`, `public_web_reference`, `publisher_catalog_reference`, `ai_original`, `teacher_original`
- `license_type`
- `source_url_or_file`
- `direct_use_allowed`
- `adaptation_allowed`
- `ai_ingestion_allowed`
- `commercial_use_allowed`
- `attribution_required`
- `attribution_text`
- `usage_mode`: `direct_import`, `adapted_import`, `structure_reference_only`, `scope_reference_only`, `rejected`
- `capture_policy`: `metadata_only`, `excerpt_with_permission`, `full_content_with_license`, `no_capture`
- `review_status`
- `review_receipt_ids`
- `source_analysis_receipt_path`

来源使用规则：

| 来源类型 | 可否直接入库 | 可否作为题型参考 | 要求 |
|---|---:|---:|---|
| 用户自有且明确授权 | 可以 | 可以 | 记录授权和用途 |
| 开放许可且允许改编 | 可以 | 可以 | 存许可、署名、版本和链接 |
| 开放许可但限制 AI 摄入 | 默认不直接喂模型 | 可以人工参考范围 | 标记 `ai_ingestion_allowed=false` |
| 商业教材 / 教辅 / 题库 | 不可以 | 只能抽象题型结构 | 禁止复制题干、数字、图形和答案 |
| 网络不明来源 | 不可以 | 谨慎人工参考 | 未核验前不得入库 |
| AI 原创生成 | 可以进入 draft | 可以 | 必须过审题、专家、QA 和激活门 |

商业题库和教材教辅的分析允许范围：

- 目录结构；
- 知识点覆盖；
- 难度梯度；
- 题型家族分布；
- 章节顺序；
- 公开样章中的少量人工观察；
- 与当前知识图谱的覆盖差异。
- 对系统现有题库的补缺建议。

不允许范围：

- 批量抓取题干；
- 保存答案和解析；
- 复制图片、图形、表格、版式；
- 改数字后入库；
- 让模型基于整本教辅或商业题库直接仿写；
- 绕过登录、付费墙、反爬或平台条款。

题源分析 receipt 至少包含：

- 来源名称和链接；
- 访问日期；
- 来源类型；
- 许可/条款观察；
- 能使用什么；
- 不能使用什么；
- 推荐 usage_mode；
- 对应图谱节点；
- 题型家族启发；
- 风险等级；
- 下一步：直接拒绝、继续核验、人工参考、请求用户授权、或进入原创生成任务。

### 5. 题库管理

管理题目本体，不混入答案、评分、学习记录。

题目必须绑定：

- 图谱节点；
- 题型家族；
- 难度；
- 目标证据；
- 题源；
- 结构指纹；
- 适用阶段；
- 状态机状态。

题目状态机：

```text
draft_imported / draft_generated
-> self_checked
-> ai_reviewed
-> expert_reviewed
-> qa_passed
-> staged
-> active
-> retired / rejected
```

`active` 只能由门禁和审核凭证推导，不能由题目 JSON 自己声明。

### 6. 答案与评分合同管理

答案和评分合同必须独立于题目存储。

每道题至少有：

- 标准答案；
- 可接受的主要解法；
- 核心得分点；
- 非关键书写要求；
- 典型错误；
- 错误到知识缺口的映射；
- 得分点到掌握维度的映射；
- 评分版本；
- 审核状态。

评分原则：

- 孩子意图正确、核心数学关系正确，轻微写法问题不能大扣分。
- 非关键书写要求作为建议，不应直接判不会。
- 答案正确但模型关系错误，不能判完全掌握。
- 模型正确但计算错，要区分计算、表达和概念。

### 7. 题库生产工作流管理

管理题库从“节点需要什么题”到“候选题是否可进入 staged”的生产过程。

核心原则：

- 题库不是凑数量，而是为每个图谱节点设计一组能暴露理解、前置断点、表达、迁移和拔高能力的题。
- 专家先定义题库结构和逐题 requirement；命题 Agent 是具体出题者；专家再审核生成结果。
- workflow 是程序状态机，不是 agent 自由聊天。每一步输入、输出、状态、退回原因和最大尝试次数都必须可记录、可重放、可审计。
- 每一道进入 staged 的题都要能回答：为什么需要这道题、它测什么、它和同节点其它题有什么结构差异、谁审核过、失败过什么、如何修正过。

生产闭环必须按如下顺序执行：

```text
图谱节点
-> 专家题型架构 brief
-> 逐题 requirement slots
-> workflow 选择一个 requirement slot
-> 命题 Agent 生成 1 道候选题
-> 程序机器检查
-> 审题 / 专家审核
-> 不合格携带结构化原因回到命题 Agent
-> 观止 QA
-> staged 候选
-> 激活门推导 active
```

#### 7.1 专家设计责任

专家不是只做最后打分。专家要先基于图谱节点和节点蓝图设计这一节点的题库要求：

- 这个节点到底需要测哪些能力；
- 哪些能力只需少量检测即可确认，避免低龄重复题；
- 哪些能力需要变式、反例、逆向或受控拔高；
- 哪些前置断点必须能被题目暴露；
- 哪些题面会显得幼稚、机械、侮辱孩子，需要禁止；
- 哪些题型容易伪难，只是数字变复杂，需要禁止；
- 每一道题在整组题里的角色是什么。

专家输出 `question_requirements`，每个 requirement 是一道题的设计任务，而不是题目本体。

每个 requirement 必须包含：

- `slot_id`
- `question_requirement_id`
- `slot_order`
- `node_id`
- `family_id`
- `difficulty`
- `coverage_role`: `entry_probe`、`core_model`、`near_transfer`、`error_repair`、`stretch`、`confirmation`
- `evidence_goal`
- `question_direction`
- `must_include`
- `must_not_include`
- `max_attempts`
- `expert_basis_profiles`

举例，数轴节点不是反复出“点 A 在哪里”：

| Slot | 作用 |
|---|---|
| 1 | 检测位置、方向、距离三要素是否分清 |
| 2 | 用局部刻度或不完整数轴判断顺序 |
| 3 | 从距离条件反推所有可能位置，暴露“距离不带方向” |
| 4 | 找错并修复“向左移动写成加法”的解法 |
| 5 | 迁移到绝对值/相反数的前置桥接 |

#### 7.2 命题 Agent 责任

命题 Agent 是具体出题者，但它没有规划权和激活权。

它只能消费单个 slot 的 bounded generation packet。packet 只能包含：

- 当前节点摘要；
- 当前 slot requirement；
- 当前题型家族说明；
- 专家建议；
- 禁止模式；
- 有限数量的已有结构指纹摘要；
- 来源边界和原创要求；
- 输出合同。

命题 Agent 不能：

- 读取全题库再自由挑方向；
- 自己增加或删除 slot；
- 一次生成不受约束的一批题；
- 自称题目 `staged`、`active` 或 `activation_eligible`；
- 用“改数字”假装新题；
- 把专家驳回原因当作可忽略建议。

#### 7.3 程序 workflow 责任

程序 workflow 负责稳定执行，不依赖 agent 自觉：

- 验证专家 brief 是否包含逐题 requirement；
- 选择下一个待生产 slot；
- 生成 one-question packet；
- 校验候选题字段、lineage、图谱/题型绑定、slot 绑定、答案合同、结构指纹、来源边界和非法自声明状态；
- 收集审题 Agent、教育专家、观止 QA 的 receipt；
- 任一 P0/P1、`needs_revision`、`reject` 自动回到命题 Agent；
- 重出时强制携带上一轮阻断原因；
- 超过 `max_attempts` 后停止自动重出，升级人工设计复核；
- 只有 receipt 和 gate 能推导 staged/active，题目 JSON 本身不能声明。

#### 7.4 生产记录

- 目标节点；
- 专家 brief id；
- `slot_id` 和 `question_requirement_id`；
- 题型家族；
- 难度；
- 目标证据；
- 当前 attempt；
- 模型与 prompt 版本；
- candidate digest；
- 结构指纹；
- 机器检查 receipt；
- 审题 / 专家 receipt；
- 观止 QA receipt；
- 驳回原因；
- 下一次重出是否携带并避开上一轮原因；
- staged / active 是否由 gate 推导。

限制：

- 不能一次把全题库喂给模型。
- 不能以凑够 1000 为目标。
- 可以一次调度多个 slot，但命题执行的原子单位仍是一个 slot 生成一道 candidate。
- 题目 JSON 不能自称 `staged`、`active` 或 `activation_eligible`；这些只能由 receipt 和 gate 推导。

### 8. 专家审核工作台

支持多个专家独立审核同一批题。

审核维度：

- 是否适合六升七；
- 是否绑定图谱节点；
- 是否有明确掌握证据；
- 是否过浅、低龄、侮辱智商；
- 是否有教学价值；
- 是否重复；
- 是否存在伪难题；
- 是否答案合同合理；
- 是否需要回退前置；
- 是否适合进入孩子端。

审核结论：

- `pass`
- `needs_revision`
- `reject`
- `pass_with_scope`

高风险题目至少需要两个专家审核：

- 拔高题；
- 应用题；
- 几何图形题；
- 多解题；
- 来源改编题；
- 曾被孩子端误判或投诉的题型。

### 9. 激活门禁

管理题目从 staged 到 active 的最后门。

必须检查：

- 图谱节点存在且启用；
- 题型家族存在；
- 题源许可可用；
- 标准答案存在；
- 评分合同存在；
- AI 审题通过；
- 至少一个教育专家通过；
- 高风险题满足多专家要求；
- 观止 QA 通过；
- 不泄漏内部字段；
- 不重复结构指纹；
- 不违反节点候选预算。

### 10. Agent / 模型配置

管理模型路由和 prompt 版本。

MVP 范围：

- agent 名称；
- 使用模型；
- prompt 版本；
- schema / envelope 版本；
- 启用状态；
- 最近失败率；
- 最近平均耗时；
- 回滚到上一版本。

限制：

- 不允许管理端绕过模型兼容适配器直接调用模型。
- 不允许把模型输出直接写入 mastery 或 active 状态。

### 11. 运行监控

用于发现系统问题，不给孩子展示后台细节。

监控项：

- 模型调用耗时；
- 队列堆积；
- 批阅失败；
- OCR 低置信；
- 题目误判；
- 重复出题；
- 卡住流程；
- stale report；
- 激活门失败原因。

### 12. 学习状态到题库调整

管理端不管理孩子个人学习进度，但允许读取 runtime 生成的聚合学习信号，用于题库内容治理。

输入只能是聚合信号和问题线索：

- 某节点题目连续误判；
- 某题型孩子能做但评分合同大扣分；
- 某节点题目过浅或重复；
- 某节点缺少近迁移题；
- 某节点拔高题过难或伪难；
- 某前置链暴露但题库没有合适 probe；
- OCR/图形题证据不足；
- 多个 attempt 显示某类错因没有被题库覆盖。

允许输出：

- 补题任务；
- 退题任务；
- 评分合同修订任务；
- 知识卡修订建议；
- 节点蓝图修订建议；
- 专家复审任务；
- 题库库存缺口报告。

禁止输出：

- 直接修改孩子 mastery；
- 直接改变今天下一题；
- 直接把未审核题推到孩子端；
- 把个人学习记录混入题库事实源。

### 13. 审计日志

所有关键变更必须留痕：

- 谁改了；
- 改了什么；
- 改前 / 改后；
- 为什么改；
- 影响哪些节点、题、答案合同、学习卡或模型配置；
- 是否需要重新 QA；
- 是否影响 active 内容。

## 题库初始化策略

初始化题库分三层：

### 第一层：结构初始化

目标是把范围、题型家族和节点蓝图做对。

允许使用：

- 人教版七上目录和项目已有知识图谱；
- 开放教材的范围结构；
- 公开样题的任务类型；
- 老师经验总结。

禁止：

- 复制商业题目；
- 改数字洗题；
- 让模型摄入未经许可的完整题库。

### 第二层：候选题初始化

目标是为 runtime 提供可选题，不是让孩子一次刷完。

来源组合：

- 授权题：直接入 draft；
- 开放许可题：按许可直接或改编入 draft；
- AI 原创题：基于节点蓝图和题型家族生成；
- 老师原创题：专家直接录入；
- 参考题型：只抽象结构，再生成原创题。

候选规模建议：

- P0 节点：12-18 道候选；
- P1 节点：8-12 道候选；
- P2 / 拔高节点：5-8 道候选。

这不是孩子每日题量。孩子每天仍然少量、自适应、按证据推进。

### 第三层：激活初始化

只有通过审核和 QA 的题才能 active。

初始化时允许存在大量 draft/staged，但儿子端只能使用 active。

## 数据对象边界

必须解耦：

| 对象 | 保存什么 | 不保存什么 |
|---|---|---|
| subject | 科目和阶段 | 题目内容 |
| knowledge_graph | 节点和依赖 | 学习卡正文、题目 |
| knowledge_card | 知识点讲解与互动内容 | 题库生产状态 |
| question_source | 来源、许可、署名、用途 | 孩子作答 |
| question_item | 题干、节点、题型、难度、结构指纹 | 评分结果、学习记录 |
| answer_contract | 标准答案、得分点、错因映射 | 题源许可 |
| review_receipt | 专家/QA/AI 审核证据 | active 自声明 |
| learning_session | 孩子每次学习流程 | 题库审核过程 |
| attempt_assessment | 每次每题答案和评分 | 题目生产状态 |
| model_config | agent 模型和 prompt 配置 | 学习掌握结论 |
| audit_log | 管理端变更证据 | 孩子端展示内容 |

## 典型流程

### 流程 0：Codex 查询题库库存

1. 管理者询问 Codex：某科目/某节点/某题型库存是否足够。
2. 管理端读取题库、答案合同、审核 receipt 和激活门结果。
3. 返回库存数量、active/staged/draft/rejected 分布、难度覆盖、题型覆盖、重复风险和缺口。
4. 如有需要，生成补题或复审任务，但不自动激活。

### 流程 A：导入一个开放许可题源

1. 管理员创建 `question_source`。
2. 填写来源链接、许可、署名、是否允许改编、是否允许 AI 摄入。
3. 题源合规 reviewer 审核。
4. 若 `direct_use_allowed=true`，可导入题目为 `draft_imported`。
5. 若只能参考结构，则只能产生 `source_pattern_note`，不能直接入库题干。
6. 所有后续题目必须保留 source lineage。

### 流程 B：AI 生成一个节点的候选题

1. 选择图谱节点。
2. 专家组基于图谱节点、节点蓝图和当前库存生成题型架构 brief。
3. 专家组在 brief 中定义逐题 requirement slots，明确每一道题测什么、属于哪个 family、难度、覆盖目标、方向和禁区。
4. workflow 校验 brief。缺少 `question_requirements` 的旧 brief 直接 blocked，不自动补 slot。
5. workflow 选择一个待生产 slot。
6. 系统给命题 Agent 一个 bounded generation packet，只包含本节点、本 slot、本家族、专家建议、禁区和有限结构指纹摘要。
7. 命题 Agent 只为这个 slot 生成 1 道 candidate，并写入 `production_lineage`。
8. 机器校验结构、字段、图谱/题型绑定、slot 绑定、答案合同、结构指纹、来源边界和自声明状态。
9. 机器检查失败则 `needs_regeneration`，驳回原因进入下一次生成禁区，并回到命题 Agent。
10. 机器检查通过后，审题 Agent 检查低价值题、答案-only 题、无证据题、伪难题。
11. 教育专家审核题目是否合理、有价值、难度真实、是否尊重六升七孩子。
12. 专家审核失败则 workflow 带着结构化意见回到命题 Agent；超过尝试次数则升级人工设计复核。
13. 观止 QA。
14. 通过后 staged，激活门再决定 active。

### 流程 C：专家驳回题目

1. 专家选择 `needs_revision` 或 `reject`。
2. 必须填写结构化原因：过浅、重复、节点不符、答案合同弱、伪难、表达差、来源风险等。
3. workflow 判断是否仍在 `max_attempts` 内。
4. 若可重出，workflow 生成下一轮 bounded packet，并把上一轮阻断原因加入 `previous_rejection_codes`。
5. 命题 Agent 重出 candidate，必须在 `production_lineage` 中携带上一轮阻断原因。
6. 机器检查若发现没有携带阻断原因，直接 `NEEDS_REGENERATION`。
7. `reject` 不允许进入 staged。
8. 超过尝试次数后，不继续让模型硬编，升级为人工设计复核：可能是 slot 本身设计错了，而不是命题 Agent 没努力。

### 流程 D：孩子端发现误判

1. attempt_assessment 被标记为 `disputed`。
2. 管理端展示题目、孩子答案、评分合同、模型判据、最终分数。
3. 测评专家判断是评分合同问题、模型判断问题、题目表达问题还是孩子答案确实不足。
4. 修复后生成新 answer_contract 版本。
5. 旧 attempt 不直接覆盖，必须追加 reassessment 记录。

### 流程 E：分析商业教辅但不复制

1. 管理端自行发现或管理者提供书名、目录、公开样章链接或已授权材料。
2. 管理端先建立 `question_source`，默认 `capture_policy=no_capture`。
3. 只提取或人工记录目录、知识点覆盖、题型家族、难度梯度和结构观察。
4. 生成 Markdown `source_analysis_receipt`。
5. 若没有授权，不保存题干、答案、解析、图片和版式。
6. 分析结果进入 `source_pattern_note`，用于指导原创题生产。
7. 新题必须由命题 Agent 或老师原创生成，并重新走审题、专家、QA 和激活门。

## Child-Safe 边界

管理端可以看到：

- source_id；
- graph node id；
- question id；
- prompt 版本；
- agent 名称；
- 模型 provider；
- rubric；
- QA receipts；
- activation gate result。

儿子端不能看到这些。

儿子端只看到：

- 题目；
- 必要图片/互动；
- 自己的得分和反馈；
- 标准答案；
- 改进方向；
- 学习进度。

## Acceptance

管理端 PRD 通过标准：

1. 听云能据此设计独立 Codex 管理模块的数据模型、命令/API、权限和迁移边界。
2. 清秋不需要设计 Web UI；只需在后续需要时审查 Codex 输出格式是否清晰、可读、可追溯。
3. 观止能据此写出题源、题库、专家审核、激活门和误判复核测试用例。
4. 镜花能据此审查管理端是否破坏 runtime 权威、child-safe 边界和证据链。
5. 题库初始化不再只有“生成 1000 道题”一种动作。
6. 已有题源的使用不再来源不明；每道题都能追溯到来源、许可、审核和激活证据。
7. 多专家审核可按题型风险配置，不强制所有题都多人审核，也不允许高风险题单人放行。
8. 管理端可以根据学习聚合信号调整题库生产计划，但不能直接管理孩子进度或写 mastery。
9. 专家 brief 缺少逐题 requirement 时，生产线必须 fail-closed，不能由 production loop 临时生成 slot。
10. 命题 Agent 的 generation packet 在 slot 模式下只能生成一道题；多题生产只能是 workflow 调度多个 slot。
11. 被驳回后的重出必须携带上一轮阻断原因，否则不能进入专家审核。

## Open Decisions

这些问题不阻塞 PRD，但阻塞技术方案：

- Codex 管理动作是否需要二次确认机制，例如激活、删除、批量下架、题源状态变更。
- 开放题源是否允许直接使用在当前家庭私有系统里，需按具体来源逐项确认。
- 题源许可审核是否需要单独的 receipt schema。
- 专家审核允许先用 Markdown/表格导入审核结论；是否需要更结构化的 reviewer 工具由技术方案决定。
- 商业题库/教材/教辅当前默认只做公开目录、样章和结构观察；若后续用户提供授权材料，再进入授权范围内的全文结构分析。
- 学习状态输入到题库调整时，允许节点、题型家族和单题误判事件三层粒度；技术方案需定义脱敏、聚合和只读边界。
- 第一批各节点的 requirement slot 数量、难度分布和 coverage role 需要由教育专家基于图谱逐节点确认；不能用固定模板硬套所有节点。

## Non-Goals

- 不做通用 SaaS 管理后台。
- 不做管理端 Web UI。
- 不做学校、班级、多学生、多老师权限系统。
- 不做商业题库爬取。
- 不做未经授权的教材/教辅导入。
- 不把题源合规 reviewer 的结论当法律意见。
- 不让管理端直接改孩子的掌握状态。
- 不让题目跳过审核直接进入儿子端。
